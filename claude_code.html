Git and Claude Code

Git is the version control system almost every modern codebase runs on. Claude Code is Anthropic's official command-line tool for agentic coding, an AI assistant that lives in your terminal, reads your project, and can make changes directly in your working tree. Used together, they turn "describe what you want" into a reviewable, committable change. This post covers what each one is, why they're worth using, and how to get both running.

What is Git?

Git is a distributed version control system: it tracks every change made to a set of files over time, lets multiple people (or an AI assistant) work on the same codebase without stepping on each other, and gives you a full history you can inspect, branch, or roll back at any point. Every commit is a snapshot, every branch is a lightweight pointer, and nothing is truly destroyed until you go out of your way to force it.

Getting started with Git

git init                        # start a new repository
git clone <url>                 # copy an existing repository
git status                      # see what's changed
git add <file>                  # stage a change
git commit -m "message"         # record a snapshot
git branch feature/my-change    # create a branch
git push origin feature/my-change  # publish it

Why use Git?

  • A safety net. Nothing is truly lost, you can always diff, revert, or check out a previous commit.
  • Branching. Experiment on a branch without touching working code, merge only once it's ready.
  • Collaboration. Multiple people (or agents) can work in parallel and merge their changes with a clear history of who changed what, and why.
  • Auditability. From a security standpoint, a clean commit history is one of the simplest ways to trace when a vulnerability was introduced and by which change.

What is Claude Code?

Claude Code is Anthropic's CLI for agentic coding. Instead of copy-pasting code into a chat window, you run claude inside your project directory and it works directly with your files: it reads the codebase for context, proposes and applies edits, runs your build and test commands, and can create commits or pull requests on your behalf, all while asking for confirmation before anything destructive or hard to reverse.

Setting up Claude Code

# install (requires Node.js)
npm install -g @anthropic-ai/claude-code

# from inside your project directory
cd my-project
claude

The first time you run it, Claude Code walks you through authenticating with your Anthropic account. From then on, running claude in any project directory drops you into an interactive session where you can ask it to explain code, fix a bug, write tests, or implement a feature, in plain English.

A typical workflow

$ git checkout -b fix/login-bug
$ claude
> there's a bug where the login form accepts empty passwords, find and fix it

  # Claude Code reads the relevant files, proposes a fix,
  # asks for confirmation, and applies the edit

$ git diff                # review exactly what changed
$ git add -A
$ git commit -m "Validate that password is non-empty on login"
$ git push origin fix/login-bug

Why Use Claude Code?

It's less about replacing the developer and more about removing friction. A few concrete reasons it's worth adding to your workflow:

  • Faster context-gathering. Dropped into an unfamiliar codebase, it can search, read, and summarize far faster than doing it by hand.
  • Git-aware by default. It understands branches, diffs, and commit history, and it favors small, reviewable, reversible changes over big destructive ones.
  • Automates the repetitive parts. Boilerplate, refactors that touch many files, writing tests for existing code, the kind of work that's simple but tedious.
  • You stay in control. Every non-trivial action (editing files, running commands, committing, pushing) is visible and confirmable, so it fits naturally into a normal review process instead of bypassing it.

Security Considerations

Treat an AI coding agent the same way you'd treat a new contributor: review its diffs before merging, keep secrets out of the repository (and out of what you paste into the terminal), and use Git's branching model so nothing lands on main without a review step. Claude Code's permission prompts for risky actions (force-pushes, destructive resets, editing files it hasn't read) exist for exactly this reason, don't reflexively approve them without reading what's being asked.

Conclusion

Git gives you a reliable history and a safe way to experiment; Claude Code gives you a fast, context-aware way to make changes within that history. Neither replaces good engineering judgment, but together they make it much faster to go from "I need to fix this" to a clean, reviewed commit.
